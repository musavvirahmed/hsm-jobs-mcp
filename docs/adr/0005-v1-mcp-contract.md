# v1 MCP contract (tools, transport, encoding)

**hsm-jobs-mcp** v1 is three snake_case tools — `search_jobs`, `get_job`, `get_index_status` — over **Streamable HTTP** (`serverInfo.name` `hsm-jobs-mcp`), with optional stdio only for local/private-release prototypes. `search_jobs` takes one of `query`|`kvk`, optional `location`, `limit` 10/20; cards omit JD body; responses include `results_truncated` and a human `result_note` (cap wording only when truncated). `get_job` looks up by the Opening’s primary URL (`primary_url` input) and returns a structured miss when absent. Results use `outputSchema` + `structuredContent` plus a text JSON mirror. Register search stays on **hsm-mcp**; identity on Openings is **register join** (CONTEXT), never a reinvented sure KvK. Auth / rate limits / paid tier are deferred.

**Opening cards** expose the primary link as `primary_url` (same name on `get_job` input). Optional `careers_url` / `ats_url` appear only when that value is present **and** differs from `primary_url` by exact string equality as stored — no duplicate second column when careers or ATS is the primary. Tool descriptions coach clients to surface each Opening’s `primary_url` as a clickable link; `result_note` stays coverage / cap / join prose only. Hard rename from the earlier card/input field `url` — no compat alias (an alias would reintroduce duplicate URL columns).

**Considered options:** dash-separated tool names (skills habit); `get_job` by opaque `job_id` or URL-or-id; two tools only (fold detail into search); text-only JSON like hsm-mcp; stdio as the product transport; re-exposing `search_sponsors`; keeping card/input `url` or a dual `url`+`primary_url` alias — rejected for wire/client fit with hsm-mcp, shared index hosting, dual-server clarity, glossary alignment with index `primary_url`, and avoiding duplicate-URL card chrome.
