# v1 MCP contract (tools, transport, encoding)

**hsm-jobs-mcp** v1 is three snake_case tools — `search_jobs`, `get_job`, `get_index_status` — over **Streamable HTTP** (`serverInfo.name` `hsm-jobs-mcp`), with optional stdio only for local/private-release prototypes. `search_jobs` takes one of `query`|`kvk`, optional `location`, `limit` 10/20 (page size), `offset` default 0; cards omit JD body; responses include `match_count` (jobs-index hits for this filter), `results_truncated`, `next_offset` when truncated, and a human `result_note` (when truncated: speak the count and tell the client to pass `next_offset`; cap wording only when truncated). Completeness is many calls, one page — same for `query` and `kvk`. `get_job` looks up by the Opening’s primary URL and returns a structured miss when absent. Results use `outputSchema` + `structuredContent` plus a text JSON mirror. Register search stays on **hsm-mcp**; identity on Openings is **register join** (CONTEXT), never a reinvented sure KvK. Auth / rate limits / paid tier are deferred.

**Considered options:** dash-separated tool names (skills habit); `get_job` by opaque `job_id` or URL-or-id; two tools only (fold detail into search); text-only JSON like hsm-mcp; stdio as the product transport; re-exposing `search_sponsors` — rejected for wire/client fit with hsm-mcp, shared index hosting, and dual-server clarity. One unbounded `search_jobs` payload or a `list_all_jobs` dump; server-side loop-then-glue; opaque cursor; omit `match_count` — rejected so every matching Opening is retrievable without flooding the model or promising a labor-market census.
