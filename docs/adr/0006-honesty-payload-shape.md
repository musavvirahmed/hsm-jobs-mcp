# Flat honesty_* keys + `"unknown"` sentinel

Tool payloads put **salary signal**, **Dutch-required**, and **sponsorship willingness** as sibling keys on each **Opening** — `honesty_salary`, `honesty_dutch_required`, `honesty_sponsorship_willingness` — beside top-level **register join** and **source class**. Every non-known honesty slot uses the JSON string `"unknown"` (not `null` or key omission). The server never emits a composite HSM-fit score or a salary-criterion meets/below verdict — clients compare raw pay text to the **salary criterion** when they have a number.

**Considered options:** nested `honesty: { … }` object (prototype variant A); deeper `salary` / `language` nests (variant C); JSON `null` / omitted keys for unknown; tagged `{ status, value }` unions; folding **register join** into honesty; server-side meets/below badges — rejected after HITL pick (B preferred) or because they invent certainty / bury identity. Nested A is a few characters shorter per card; B’s `honesty_` prefix is slightly costlier in tokens but keeps JD-silence fields greppable and flat for models. Real token wins stay elsewhere: no JD body on `search_jobs` cards, low `limit`, enums not prose.
