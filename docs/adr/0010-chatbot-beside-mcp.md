# Chatbot beside MCP clients (off Worker origin)

**hsm-jobs-mcp** keeps Streamable HTTP `/mcp` for **MCP clients** (Claude Code, GitHub Copilot CLI, Cursor, any MCP client) and adds a parallel **chatbot**: a first-party website conversation UI so a **kennismigrant** can ask without installing an AI-IDE or attaching MCP servers. The **chatbot** is not a jobs portal on Worker `GET /` — [ADR 0007](./0007-post-v1-packaging-discovery.md) still forbids Opening search / sponsor directory / chatbot on that origin. Host it on a separate origin (today [https://easy-hsm-jobs.framer.website/](https://easy-hsm-jobs.framer.website/); a future subdomain such as `easy-hsm-jobs.musavvir.work` is optional, not a blocker). Do not promote it from the product README or `/` until deliberately decided. Guts are open: the **chatbot** may wrap an **MCP client** or a hosted model calling **v1 jobs tools**; that choice is not locked here. A stub (canned answers) may precede a live wire; staging details belong in tickets.

**Considered options:** put the **chatbot** on Worker `GET /` (reopen portal-on-`/`); treat the **chatbot** as the only human path and drop Connect / **MCP client** packaging; lock guts to “must wrap Claude Code or Copilot CLI” or “must use a hosted model only” — rejected so MCP discovery stays for experts, the no-CLI path stays a separate surface, and implementation can change without rewriting the boundary.
